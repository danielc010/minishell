MINISHELL — PROJECT PLAN & SCHEDULE
=====================================

ARCHITECTURE OVERVIEW
---------------------
Input (readline) -> Lexer -> Parser -> Expander -> Executor

COMPONENTS TO BUILD
-------------------
Lexer       - Splits raw input into tokens (words, pipes, redirections, quotes)
Parser      - Builds a command list / AST from tokens
Expander    - Expands $VAR, $?, handles quote stripping
Executor    - Forks, execs, pipes, redirects
Built-ins   - echo, cd, pwd, export, unset, env, exit
Signals     - ctrl-C, ctrl-D, ctrl-\
Environment - Own copy of envp, managed internally


PHASE 1 — FOUNDATION (Days 1–3)
---------------------------------
[ ] Project structure: src/, include/, libft/
[ ] Makefile with all required rules
[ ] readline loop with prompt + add_history
[ ] Global signal variable skeleton (only 1 global allowed)
[ ] Basic env copy from envp at startup

Goal: Shell boots, accepts input, exits cleanly.


PHASE 2 — LEXER / TOKENIZER (Days 4–7)
----------------------------------------
[ ] Token types: WORD, PIPE, REDIR_IN, REDIR_OUT, HEREDOC, REDIR_APPEND
[ ] Handle single quotes '...' — no interpretation inside
[ ] Handle double quotes "..." — only $ interpreted inside
[ ] Detect unclosed quotes -> error, don't execute
[ ] Don't interpret \ or ;

Goal: Input correctly split into a token list.


PHASE 3 — PARSER (Days 8–11)
------------------------------
[ ] Build a t_cmd list from tokens (one node per pipe segment)
[ ] Each node holds: argv[], list of redirections, pipe flags
[ ] Validate syntax (no bare |, no double redirects, etc.)

Goal: "ls -la | grep foo > out.txt" becomes a clean command structure.


PHASE 4 — EXPANDER (Days 12–13)
---------------------------------
[ ] Expand $VAR from env
[ ] Expand $? to last exit status
[ ] Strip quotes after expansion
[ ] Respect quote context (no expansion inside '...')

Goal: echo "$HOME" and echo '$HOME' behave like bash.


PHASE 5 — EXECUTOR (Days 14–19)
---------------------------------
[ ] PATH resolution for executables
[ ] fork + execve for external commands
[ ] Pipe chain: pipe(), dup2(), close unused fds
[ ] Redirections: <, >, >> via open() + dup2()
[ ] Heredoc <<: read lines until delimiter, write to temp pipe
[ ] waitpid / exit status tracking

Goal: "cat file | grep word > result" works end-to-end.


PHASE 6 — BUILT-INS (Days 20–23)
----------------------------------
[ ] echo with -n
[ ] cd (relative + absolute, update PWD/OLDPWD)
[ ] pwd
[ ] export (add/update env var, print sorted if no args)
[ ] unset
[ ] env
[ ] exit (with optional status code)

Key: cd, export, unset, exit must run in the PARENT process (no fork).


PHASE 7 — SIGNALS (Days 24–25)
--------------------------------
[ ] ctrl-C (SIGINT): print newline, show new prompt
[ ] ctrl-D (EOF): exit shell
[ ] ctrl-\ (SIGQUIT): do nothing in interactive mode
[ ] Different signal behaviour during child execution vs. interactive prompt


PHASE 8 — TESTING & POLISH (Days 26–30)
-----------------------------------------
[ ] Valgrind — no leaks in your code (readline leaks are OK)
[ ] Edge cases: empty input, spaces only, | at start/end, nested quotes
[ ] Compare all behaviour against real bash
[ ] Update README with accurate info + AI usage section


BONUS — (After mandatory is solid)
------------------------------------
[ ] && and || with parentheses for grouping
[ ] * wildcard expansion in current directory


KEY RULES TO REMEMBER
---------------------
- Only 1 global variable — must only store a signal number
- No norm errors — project gets 0 if norm fails
- No memory leaks in your code (use valgrind regularly)
- Bash is the reference — when in doubt, test it in bash


SUGGESTED DAILY RHYTHM
-----------------------
1. Start each session by reviewing what bash does for the feature you're building
2. Implement, test manually, check for leaks
3. Before ending: commit working state to git
